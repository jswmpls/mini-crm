# Мини-CRM «Объекты и задачи»

Небольшая CRM для строительной компании: постановщик создаёт объекты и задачи, исполнитель берёт их в работу и отправляет на проверку. Две роли, цикл статусов и неизменяемая история изменений.

**Стек:** React + TypeScript (Vite), Supabase (Postgres + Auth), React Router.  
Права доступа и переходы статусов проверяются на уровне базы (RLS и триггеры), интерфейс только показывает доступные действия.

## Быстрый старт

1. Создайте проект в [Supabase](https://supabase.com).
2. В **SQL Editor** выполните по порядку:
   - `supabase/schema.sql` - схема, RLS, триггеры.
   - Создайте в **Authentication → Users** (с включённым **Auto Confirm User**):
     - `manager@demo.test` / `12345678`
     - `executor1@demo.test` / `12345678`
     - `executor2@demo.test` / `12345678`
   - `supabase/demo_data.sql` - демо-объекты и задачи в разных статусах.
3. Отключите открытую регистрацию: **Authentication → Sign In / Providers → выключить _Allow new users to sign up_**.
4. В корне проекта создайте `.env` (см. `.env.example`):

   ```env
   VITE_SUPABASE_URL=https://<project-ref>.supabase.co
   VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
   ```

5. Запустите:
   ```bash
   npm install
   npm run dev
   ```

Приложение откроется на [http://localhost:5173](http://localhost:5173).

## Безопасность

- **RLS включён на всех таблицах.** Исполнитель видит только свои задачи и объекты, в которых они есть. Правила работают и при прямых запросах к Supabase, в обход интерфейса.
- **Переходы статусов** проверяются триггером `tasks_before_update`: разрешены только переходы из ТЗ и только для нужной роли. Возврат на доработку без комментария отклоняется.
- **История неизменяема.** Записи в `task_status_history` создаются только триггером, у роли `authenticated` есть только `select` - подделать или удалить историю через API нельзя.
- **Роли.** Роль по умолчанию - `executor`, менять её можно только вручную в Supabase. Исполнитель не может выдать себе роль постановщика.
- **Ключи.** В репозиторий и во фронтенд попадает только publishable-ключ. `.env` в `.gitignore`, в репозитории - только `.env.example` без значений.

## Решения и допущения

- **Демо-пользователи** создаются вручную в Supabase (открытая регистрация отключена). Для удобства проверки я задала всем трём одинаковый пароль `12345678`.
- **Комментарий при возврате на доработку** обязателен только при переходе `in_review → rework`, как в ТЗ. Для остальных переходов — необязателен.
- **Удаление объекта** каскадно удаляет его задачи (`on delete cascade`). Доступно только постановщику.
- **История создания** задачи пишется триггером с `from_status = null` - так видно полный путь задачи.
- **Что я не делала:** уведомлений, вложений, пагинации и отдельного экрана «все задачи» для постановщика (он видит задачи через объекты и карточку задачи).
